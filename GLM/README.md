# GLM — Claude Code на Z.AI: переключатель и воркер

В папке два независимых инструмента, и путать их дорого:

- **`switch-claude.ps1`** — переключает **сам** Claude Code на Z.AI, правя `~/.claude/settings.json`.
  Меняет оркестратора. Ломает вкладку Code в десктоп-приложении, пока не вернёшь обратно.
- **`glm-run.py`** — отдаёт **одну задачу** воркеру на GLM дочерним процессом, не трогая
  `settings.json` вообще. Ничего вокруг вызова не меняет. Это аналог `agy-run.py`.

Дальше сначала про переключатель, потом про обёртку.

## Переключатель

`switch-claude.bat` открывает меню:

- **1** — подмешивает ключи Z.AI в блок `env` файла `~/.claude/settings.json` и убирает из него
  `ANTHROPIC_API_KEY` и `CLAUDE_CODE_OAUTH_TOKEN`, чтобы они не ушли в Z.AI рядом с ключом Z.AI.
  Если ключа ещё нет в `~/.claude/zai_api_key.txt`, спрашивает его (ввод не отображается) и
  сохраняет туда. Перед первой правкой снимает копию `settings.json` в
  `settings.anthropic.backup.json` — только если файл разбирается как JSON и ещё не в режиме GLM.
  Режим GLM определяется по значению `env.ANTHROPIC_BASE_URL`, а не по упоминанию `api.z.ai`
  где-либо в файле. Битый `settings.json` не трогается и в копию не попадает.
- **2** — убирает из `env` ключи, которыми управляет режим GLM (ключи Z.AI и два снятых в пункте 1),
  и возвращает те из них, что были в резервной копии, с прежними значениями. Остальные ключи `env`,
  в том числе добавленные в режиме GLM, остаются. Без копии удаляются только ключи Z.AI.
- **3** — запускает `claude` в этом окне; в режиме Anthropic перед запуском убирает ключи Z.AI из
  окружения окна.
- **4** — сменить или ввести ключ Z.AI: спрашивает новый ключ и перезаписывает им
  `~/.claude/zai_api_key.txt` (пустой ввод ничего не меняет). Если сейчас активен режим GLM, сразу
  повторяет пункт 1, чтобы новый ключ попал и в `settings.json`. Этот же файл читает `glm-run.py`,
  так что смена ключа действует и на воркер.
- **0** — выход из меню.

Остальные ключи `settings.json` (`permissions.allow` с разрешениями на `agy-run.py` и
`glm-run.py`, `autoMode`) не затрагиваются ни в одну сторону.

Запись атомарная: новый `settings.json` пишется во временный `settings.json.tmp` рядом,
перечитывается и разбирается, и только потом заменяет оригинал. Если проверка не прошла, оригинал
остаётся как был.

Значения ключей взяты из [гайда Z.AI для Claude Code](https://docs.z.ai/devpack/tool/claude),
раздел ручной настройки, включая суффикс `[1m]` и парный к нему
`CLAUDE_CODE_AUTO_COMPACT_WINDOW: 1000000` — это способ включить окно на 1M токенов.

## Где это работает, а где нет

| Поверхность | Читает `env` из `settings.json` | Переключится этим скриптом |
|---|---|---|
| Терминальный CLI (`claude`) | да | **да** |
| Десктоп-приложение, вкладка Code | да, но не для маршрутизации запросов | **нет** |
| Расширение VS Code | нет, нужен `claudeCode.environmentVariables` | нет |

Десктоп-приложение читает тот же `~/.claude/settings.json` — оттуда берутся разрешения, хуки,
скиллы. Но **адрес модели** оно берёт из другого места:

> The desktop app reads gateway routing from its third-party inference configuration, not from
> `ANTHROPIC_BASE_URL` or `settings.json`.
> — [Connect Claude Code to an LLM gateway](https://code.claude.com/docs/en/llm-gateway-connect#desktop-app)

Поэтому пункт 1 меняет поведение только нового запуска `claude` в терминале. Вкладка Code
продолжит работать на Anthropic, но имена моделей из `env` подхватит и начнёт падать на служебных
вызовах. Режим GLM — только на время работы в терминальном CLI; перед работой в
десктоп-приложении возвращайтесь пунктом 2. Как это было обнаружено — `docs/incidents.md`.

## Если после переключения или обновления claude не работает

1. **Закрыть десктоп-приложение полностью, включая иконку в трее, и открыть заново.** Приложение
   подхватывает блок `env` из `settings.json` на лету и держит его после того, как ключи из файла
   удалены; терминалы, открытые из него, наследуют `ANTHROPIC_AUTH_TOKEN` и переменные моделей
   `glm-5.3`. Без перезапуска — в самом терминале посмотреть `Get-ChildItem Env:ANTHROPIC*` и
   снять лишнее через `Remove-Item Env:...` перед запуском `claude`.
2. **Проверить бинарник:**
   `(Get-Item "$env:APPDATA\npm\node_modules\@anthropic-ai\claude-code\bin\claude.exe").Length`.
   Файл около 500 байт — это заглушка, оставшаяся после того, как политика npm `allow-scripts`
   заблокировала postinstall. Постоянное исправление:
   `npm config set allow-scripts=@anthropic-ai/claude-code --location=user`. Разовая починка —
   `node install.cjs` в каталоге этого пакета.

Датированные наблюдения, из которых выведены эти проверки, — `docs/incidents.md`.

## Если нужен GLM именно в десктоп-приложении

Это отдельный, не связанный со скриптом путь — «Claude Desktop on 3P», рассчитанный на
корпоративное развёртывание через MDM, но локальная настройка тоже поддерживается:

1. Help → Troubleshooting → **Enable Developer Mode** (приложение перезапустится, появится меню
   Developer).
2. Developer → **Configure Third-Party Inference…**
3. Inference provider = **Gateway**, дальше карточка Gateway credentials:
   - Gateway base URL — `https://api.z.ai/api/anthropic`
   - Gateway API key — ключ Z.AI
   - Credential kind — **Static API key**
   - Gateway auth scheme — **Bearer** (значение по умолчанию; именно так Z.AI и ожидает ключ)

Подводный камень: список моделей. Автоподбор через `GET /v1/models` отфильтровывает всё, что не
похоже на Claude, а `glm-5.3` под этот фильтр не попадает — picker окажется пустым. Модели нужно
задать явным списком `inferenceModels` полными идентификаторами, а окно на 1M включается полем
`supports1m` на элементе списка, а не суффиксом `[1m]`.

Ничего из этого не проверено на практике: описание собрано из документации
([Deploy Claude Desktop on 3P with an LLM gateway](https://claude.com/docs/third-party/claude-desktop/gateway)),
а сам скрипт этой конфигурации не касается.

## Отдельный `claude` в PATH

Если в PATH `claude` нет, пункт 3 меню берёт самую свежую версию из десктоп-приложения
(`%APPDATA%\Claude\claude-code\<версия>\claude.exe`). Текущую версию установленного `claude`
показывает `claude --version` (держится на latest); ставить его нужно с разрешённым postinstall —
см. «Если после переключения или обновления claude не работает», пункт 2.

**Подводный камень для любого кода, который зовёт `claude` из подпроцесса.** `Get-Command claude`
и `shutil.which("claude")` возвращают не исполняемый файл, а npm-шим `claude.CMD`, который
`CreateProcess` запустить не может — Python падает на нём без shell. Настоящий бинарник лежит
рядом с шимом: `<префикс npm>\node_modules\@anthropic-ai\claude-code\bin\claude.exe`.
`glm-run.py` поэтому разрешает шим в этот путь, а не доверяет `which`.

## Переключатель — не делегирование

Скрипт меняет модель, на которой работает сам Claude Code, — это замена оркестратора, а не
передача задачи исполнителю. Передача одной задачи воркеру (подпроцесс получает бриф и
возвращает результат) — `glm-run.py` в этой же папке, следующий раздел.

## `glm-run.py` — GLM как воркер

Запускает `claude --print` дочерним процессом и выставляет `ANTHROPIC_BASE_URL`,
`ANTHROPIC_AUTH_TOKEN` и имена моделей **только в окружении этого процесса**.
`~/.claude/settings.json` не читается, не пишется и вообще не участвует: в каком бы режиме
переключатель ни оставил файл, адрес эндпоинта для вызова решается внутри `glm-run.py`.

```
python "C:/Users/cupik/.claude/skills/workers/GLM/glm-run.py" --dir . --prompt "..."
python "C:/Users/cupik/.claude/skills/workers/GLM/glm-run.py" --dir . --prompt-file brief.txt --timeout-min 20
python "C:/Users/cupik/.claude/skills/workers/GLM/glm-run.py" --no-tools --prompt "..."     # без инструментов, чистое рассуждение
```

Драйвер зовёт то же самое как `python "${CLAUDE_PLUGIN_ROOT}/GLM/glm-run.py" ...`. Путь через
junction плагина без вопросов проходит из любого каталога: почему — в разделе «Плагин, junction
и разрешения» ниже.

Контракт тот же, что у `AGY/agy-run.py`: один бриф внутрь, один ответ в stdout,
стоимость вызова в stderr. Коды выхода у обеих обёрток одинаковые: **0** — успех; **1** — воркер
упал или сообщил об ошибке; **2** — отказ до вызова (неверные аргументы, запрещённый каталог,
грязное дерево, плохой или не-UTF-8 файл брифа, нет ключа или бинарника, в том числе
`GLM_CLAUDE_BIN`, указывающий не на файл); **3** — таймаут. Общий код обёрток —
`lib/workers_common.py`, тесты — `python -m unittest discover -s tests`. Отличия вынуждены самим
инструментом:

- **бриф идёт в stdin, а не в argv.** `claude --print` читает stdin, когда позиционный промпт не
  задан (проверено 2026-09-15). Это снимает потолок командной строки в 32767 символов, из-за
  которого `agy-run` умеет подсовывать бриф файлом, и заодно убирает бриф из списка процессов.
- **ключ читается из `~/.claude/zai_api_key.txt`** и передаётся в окружении. Аргументом он не
  передаётся никогда: argv на Windows читается любым процессом.
- **`--setting-sources project,local`** — дочерний процесс не читает `~/.claude/settings.json`,
  то есть режим переключателя на вызов не влияет. Проверено контрольным опытом 2026-09-15, а не
  выведено из документации: в тестовый репозиторий положен `.claude/settings.json` с
  `env.GLM_PROBE_PROJECT`, и воркера попросили напечатать эту переменную. С `project` в списке
  источников она приходит, без `project` — `None`. Значит блок `env` применяется только от
  загруженных источников, и отсутствие `user` в списке исключает пользовательский файл.
  Побочно это значит, что воркер не наследует пользовательские хуки и разрешения; для воркера
  это и требовалось.

  Обратная сторона: **проектный** `.claude/settings.json` воркер читает, вместе с его блоком
  `env` и хуками. Для своего репозитория это и нужно, но `--dir` на чужой репозиторий означает
  исполнение его настроек.
- **MCP погашены** через `--strict-mcp-config` без единого `--mcp-config`, скиллы — через
  `--disable-slash-commands`, файлы сессий — через `--no-session-persistence`.
- **фан-аут запрещён**: `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=0` плюс инструмент субагента
  запрещён по имени (`--disallowed-tools Task Agent` — имя менялось между версиями, поэтому
  оба). Проверено вызовом, который прямо просили делегировать субагенту: воркер ответил
  `NO SUBAGENT`.
- **отказ на грязном дереве** — как у `agy-run`, и по той же причине: правки воркера
  откатываются только через `git checkout .`, а для этого до вызова дерево должно быть чистым.
  `--force` снимает эту проверку, проверку запрещённых каталогов — не снимает.

### Что стоит вызов

Замеры (пустой вызов, вызов с инструментами, создание файла, настоящая многофайловая задача) —
в скиллах `glm` и `agy`, раздел «What a call costs» (`skills/glm/SKILL.md`,
`skills/agy/SKILL.md`). Вывод из них:
делегирование оценивается по цене реальной многофайловой задачи (~296 600 токенов input плюс
cache-read, примерно в семнадцать раз больше порога вызова с инструментами), а не по цене создания
одного файла.

**`total_cost_usd` в отчёте — не счёт от Z.AI.** Claude Code считает его по своей таблице цен, в
которой GLM нет; в JSON это помечено как `"costBasis":"unknown"`. Обёртка печатает цифру, потому
что относительное сравнение вызовов по ней работает, и помечает её, потому что принимать её за
сумму к оплате нельзя. Реальный показатель — токены.

`[claude-code:unrecognized_model]` в stderr по той же причине: клиент не знает `glm-5.3[1m]`.
На результат не влияет — `modelUsage` в ответе подтверждает и модель, и `contextWindow` 1000000.

### 401 «token expired or incorrect» при рабочем ключе

Наблюдение 2026-09-26. Вызов из сессии десктоп-приложения падал с
`API Error: 401 token expired or incorrect` после 11 попыток и ~284 с, хотя прямой запрос к
`https://api.z.ai/api/anthropic/v1/messages` с тем же ключом отвечал 200. Причина — переменная
`CLAUDE_CODE_ENTRYPOINT=claude-desktop`, которую процесс Claude Code в приложении передаёт всем
своим дочерним: с ней дочерний `claude` берёт авторизацию хоста вместо `ANTHROPIC_AUTH_TOKEN` и
отправляет в Z.AI не тот токен. Проверено по одной: без неё вызов проходит за 10 с, без
`CLAUDE_CODE_SDK_HAS_HOST_AUTH_REFRESH` или `CLAUDE_CODE_OAUTH_SCOPES` — нет. `child_env()`
теперь снимает её и остальные переменные хост-сессии.

Если 401 вернётся, сначала проверьте ключ прямым запросом, а не пересоздавайте его: ошибка
одинаково выглядит и для просроченного ключа, и для подменённого токена.

## Плагин, junction и разрешения

Этот репозиторий — плагин Claude Code `workers`. Установленных копий обёртки нет: вызов идёт
прямо в `GLM/glm-run.py` этого репозитория. Вне репозитория — два пути, и оба часть той же системы:

- `~/.claude/skills/workers` — junction на этот репозиторий. Через него Claude Code грузит плагин
  на месте как `workers@skills-dir`; по умолчанию он выключен и включается в проекте командой
  `claude plugin enable workers@skills-dir --scope local` в каталоге проекта (`disable` —
  выключить). Скиллы
  `workers:glm` и остальные видны только там, где плагин включён. Содержимое правится здесь, не
  через junction; после правки — `/reload-plugins`.
- `~/.claude/settings.json` — в `permissions.allow` записи на команды
  `python "C:/Users/cupik/.claude/skills/workers/GLM/glm-run.py"`,
  `python "C:/Users/cupik/.claude/skills/workers/AGY/agy-run.py"` и
  `python "C:/Users/cupik/.claude/skills/workers/scripts/check.py"`, в прямых и обратных слэшах.
  Запись сверяется с текстом команды, а не с файлом на диске, поэтому путь через junction
  проходит без вопросов из любого проекта, а `python GLM/glm-run.py` из корня репозитория или
  `python glm-run.py` изнутри `GLM/` тексту не соответствуют, и подтверждение спросят. Аргументы
  запись не ограничивает, поэтому обёртка сама проверяет `--dir`.

Проверить оба воркера разом — `/workers:check` в сессии или `python scripts/check.py` в корне
репозитория: по одному крошечному вызову каждого, строка `OK`, `ACCOUNT` или `DOWN` на воркер.
Для ручного теста обёртку можно звать и напрямую, как в примерах выше.

## Проверка, что режим действительно сменился

В сессии Claude Code — команда `/status`: она показывает провайдера, base URL и источник
credential. Это надёжнее, чем смотреть в `settings.json`, потому что отвечает на вопрос, куда
реально уходят запросы.

## Файлы, которые создаёт скрипт

Оба появляются при первом переключении на GLM, в `~/.claude/` (вне этого репозитория):

- `zai_api_key.txt` — введённый ключ, открытым текстом;
- `settings.anthropic.backup.json` — копия `settings.json`, снятая перед первой правкой.
