# GLM — Claude Code на Z.AI: переключатель и воркер

В папке два независимых инструмента, и путать их дорого:

- **`switch-claude.ps1`** — переключает **сам** Claude Code на Z.AI, правя `~/.claude/settings.json`.
  Меняет оркестратора. Ломает вкладку Code в десктоп-приложении, пока не вернёшь обратно.
- **`glm-run.py`** — отдаёт **одну задачу** воркеру на GLM дочерним процессом, не трогая
  `settings.json` вообще. Ничего вокруг вызова не меняет. Это аналог `agy-run.py`.

Дальше сначала про переключатель, потом про обёртку.

## Переключатель

`switch-claude.bat` → меню → пункт 1 подмешивает ключи Z.AI в блок `env` файла
`~/.claude/settings.json`, пункт 2 возвращает всё как было. Остальные ключи файла
(`permissions.allow` с разрешением на `agy-run`, `autoMode`) не затрагиваются ни в одну сторону.

Значения ключей взяты из [гайда Z.AI для Claude Code](https://docs.z.ai/devpack/tool/claude),
раздел ручной настройки, включая суффикс `[1m]` и парный к нему
`CLAUDE_CODE_AUTO_COMPACT_WINDOW: 1000000` — это способ включить окно на 1M токенов.

## Где это работает, а где нет

| Поверхность | Читает `env` из `settings.json` | Переключится этим скриптом |
|---|---|---|
| Терминальный CLI (`claude`) | да | **да** |
| Десктоп-приложение, вкладка Code | да, но не для маршрутизации запросов | **нет** |
| Расширение VS Code | нет, нужен `claudeCode.environmentVariables` | нет |

Десктоп-приложение читает тот же `~/.claude/settings.json` — оттуда берутся разрешения, хуки,
скиллы. Но **адрес модели** оно берёт из другого места:

> The desktop app reads gateway routing from its third-party inference configuration, not from
> `ANTHROPIC_BASE_URL` or `settings.json`.
> — [Connect Claude Code to an LLM gateway](https://code.claude.com/docs/en/llm-gateway-connect#desktop-app)

Поэтому пункт 1 меняет поведение только нового запуска `claude` в терминале. Вкладка Code
продолжит работать на Anthropic.

### Но безвредным для десктопа переключение не является

Наблюдение 2026-09-14, на живой сессии. При активном режиме GLM вкладка Code начала падать с
сообщением `glm-5.3[1m] is temporarily unavailable` при каждой операции, которой нужен служебный
вызов модели (в auto mode — классификатор безопасности команд). Чтение файлов и поиск продолжали
работать, выполнение команд — нет.

То есть десктоп **читает `ANTHROPIC_DEFAULT_*_MODEL` из `env`**, хотя `ANTHROPIC_BASE_URL` для
маршрутизации игнорирует. Получается худший из вариантов: имена моделей подменились, а адрес
эндпоинта — нет, и сессия просит несуществующую для неё модель.

Практический вывод: **перед работой в десктоп-приложении возвращайтесь пунктом 2.** Режим GLM —
только на время работы в терминальном CLI.

### Возврата пунктом 2 недостаточно — нужен перезапуск сессии

Claude Code читает `settings.json` один раз, при старте сессии. После пункта 2 файл чист, но
уже открытая вкладка Code продолжает держать старые имена моделей и падать с той же ошибкой.
Проверено 2026-09-14: `settings.json` без единого упоминания Z.AI, а Bash в текущей сессии
по-прежнему отказывает. Лечится только новой сессией.

То же верно и в обратную сторону: пункт 1 не действует на уже запущенные сессии.

### Новой сессии тоже мало — перезапускайте приложение целиком

Наблюдение 2026-09-26. Процесс Claude Code, запущенный из приложения в 11:39, после пункта 1 в
11:44 получил ключи Z.AI **в собственное окружение**: приложение подхватывает блок `env` на лету.
После пункта 2 в 11:46 файл снова был чист, а процесс продолжал держать `ANTHROPIC_AUTH_TOKEN`
(ключ Z.AI), `ANTHROPIC_DEFAULT_*_MODEL=glm-5.3*`, `API_TIMEOUT_MS`,
`CLAUDE_CODE_AUTO_COMPACT_WINDOW` и `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`. Удаление ключа из
файла не снимает его с процесса. Всё, что запущено из такого процесса, включая терминал, наследует
эти значения, и `claude` в этом терминале уходит на `api.anthropic.com` с ключом Z.AI, так что
войти через `/login` не получается.

`settings.json`, переменные Windows и профили PowerShell при этом чистые — искать на диске нечего.

Лечится так: закрыть приложение полностью, включая иконку в трее, и открыть заново. Скрипт
напоминает об этом после пунктов 1 и 2, если видит запущенный `claude`, а пункт 3 в режиме
Anthropic перед запуском убирает ключи Z.AI из окружения своего окна.

## Установка отдельного CLI: postinstall обязателен

`npm i -g @anthropic-ai/claude-code` под npm с политикой `allowScripts` не доводит установку до
конца — postinstall блокируется. Это не косметика: судя по комментарию в `cli-wrapper.cjs` самого
пакета, postinstall копирует нативный бинарник поверх `bin/claude.exe`, а шим `claude.cmd`
вызывает именно этот путь. Без него шим указывает на заглушку.

Ставить так:

```
npm install -g --allow-scripts=@anthropic-ai/claude-code @anthropic-ai/claude-code
```

Проверка — `claude --version`, ожидается `<версия> (Claude Code)`.

**Автообновление этот флаг не передаёт.** 2026-09-26 Claude Code сам обновился на новую версию
командой `npm install --global @anthropic-ai/claude-code@<версия>`, npm заблокировал
postinstall («install scripts blocked because they are not covered by allowScripts»), и
`bin\claude.exe` снова стал заглушкой на 500 байт — `claude` перестал запускаться вовсе. Поэтому
разрешение выдано один раз на уровне пользователя, в `~/.npmrc`:

```
npm config set allow-scripts=@anthropic-ai/claude-code --location=user
```

Проверено тем же `npm install --global` без флагов: postinstall отработал с `code: 0`, бинарник
245 МБ, `claude --version` отвечает. Если заглушка всё же вернулась — починка на месте:
`node install.cjs` в `%APPDATA%\npm\node_modules\@anthropic-ai\claude-code`.

## Если нужен GLM именно в десктоп-приложении

Это отдельный, не связанный со скриптом путь — «Claude Desktop on 3P», рассчитанный на
корпоративное развёртывание через MDM, но локальная настройка тоже поддерживается:

1. Help → Troubleshooting → **Enable Developer Mode** (приложение перезапустится, появится меню
   Developer).
2. Developer → **Configure Third-Party Inference…**
3. Inference provider = **Gateway**, дальше карточка Gateway credentials:
   - Gateway base URL — `https://api.z.ai/api/anthropic`
   - Gateway API key — ключ Z.AI
   - Credential kind — **Static API key**
   - Gateway auth scheme — **Bearer** (значение по умолчанию; именно так Z.AI и ожидает ключ)

Подводный камень: список моделей. Автоподбор через `GET /v1/models` отфильтровывает всё, что не
похоже на Claude, а `glm-5.3` под этот фильтр не попадает — picker окажется пустым. Модели нужно
задать явным списком `inferenceModels` полными идентификаторами, а окно на 1M включается полем
`supports1m` на элементе списка, а не суффиксом `[1m]`.

Ничего из этого не проверено на практике: описание собрано из документации
([Deploy Claude Desktop on 3P with an LLM gateway](https://claude.com/docs/third-party/claude-desktop/gateway)),
а сам скрипт этой конфигурации не касается.

## Отдельный `claude` в PATH

Если в PATH `claude` нет, пункт 3 меню берёт самую свежую версию из десктоп-приложения
(`%APPDATA%\Claude\claude-code\<версия>\claude.exe`). Текущую версию установленного `claude`
показывает `claude --version` (держится на latest); симптомы сломанного postinstall и починка — в
разделе выше.

**Подводный камень для любого кода, который зовёт `claude` из подпроцесса.** `Get-Command claude`
и `shutil.which("claude")` возвращают не исполняемый файл, а npm-шим `claude.CMD`, который
`CreateProcess` запустить не может — Python падает на нём без shell. Настоящий бинарник лежит
рядом с шимом: `<префикс npm>\node_modules\@anthropic-ai\claude-code\bin\claude.exe`.
`glm-run.py` поэтому разрешает шим в этот путь, а не доверяет `which`.

## Переключатель — не делегирование

Скрипт меняет модель, на которой работает сам Claude Code, — это замена оркестратора, а не
передача задачи исполнителю. Передача одной задачи воркеру (подпроцесс получает бриф и
возвращает результат) — `glm-run.py` в этой же папке, следующий раздел.

## `glm-run.py` — GLM как воркер

Запускает `claude --print` дочерним процессом и выставляет `ANTHROPIC_BASE_URL`,
`ANTHROPIC_AUTH_TOKEN` и имена моделей **только в окружении этого процесса**.
`~/.claude/settings.json` не читается, не пишется и вообще не участвует: в каком бы режиме
переключатель ни оставил файл, адрес эндпоинта для вызова решается внутри `glm-run.py`.

```
python C:/Users/cupik/.claude/bin/glm-run.py --dir . --prompt "..."
python C:/Users/cupik/.claude/bin/glm-run.py --dir . --prompt-file brief.txt --timeout-min 20
python C:/Users/cupik/.claude/bin/glm-run.py --no-tools --prompt "..."     # без инструментов, чистое рассуждение
```

**Звать по абсолютному пути к установленной копии, из любого каталога.** Разрешение в
`~/.claude/settings.json` записано как `Bash(python C:/Users/cupik/.claude/bin/glm-run.py:*)` и
сверяется с текстом команды, а не с файлом на диске. В таком написании команда проходит без
вопросов из любого проекта; `python GLM/glm-run.py` из корня репозитория или `python glm-run.py`
изнутри `GLM/` тексту не соответствуют, и подтверждение спросят. Версионный исходник остаётся в
этом репозитории (`glm-agy-cc-proxy/GLM/glm-run.py`) — здесь его история; вызов идёт в
установленную копию `~/.claude/bin/glm-run.py`, поэтому после правки исходника копию нужно
переписать поверх неё заново.

Скилл `glm` виден во всех проектах через junction `~/.claude/skills/glm` → `.claude/skills/glm`
этого репозитория. Правится только здесь.

Контракт тот же, что у `~/.claude/bin/agy-run.py`: один бриф внутрь, один ответ в stdout,
стоимость вызова в stderr, `exit 0` только при успехе. Отличия вынуждены самим инструментом:

- **бриф идёт в stdin, а не в argv.** `claude --print` читает stdin, когда позиционный промпт не
  задан (проверено 2026-09-15). Это снимает потолок командной строки в 32767 символов, из-за
  которого `agy-run` умеет подсовывать бриф файлом, и заодно убирает бриф из списка процессов.
- **ключ читается из `~/.claude/zai_api_key.txt`** и передаётся в окружении. Аргументом он не
  передаётся никогда: argv на Windows читается любым процессом.
- **`--setting-sources project,local`** — дочерний процесс не читает `~/.claude/settings.json`,
  то есть режим переключателя на вызов не влияет. Проверено контрольным опытом 2026-09-15, а не
  выведено из документации: в тестовый репозиторий положен `.claude/settings.json` с
  `env.GLM_PROBE_PROJECT`, и воркера попросили напечатать эту переменную. С `project` в списке
  источников она приходит, без `project` — `None`. Значит блок `env` применяется только от
  загруженных источников, и отсутствие `user` в списке исключает пользовательский файл.
  Побочно это значит, что воркер не наследует пользовательские хуки и разрешения; для воркера
  это и требовалось.

  Обратная сторона: **проектный** `.claude/settings.json` воркер читает, вместе с его блоком
  `env` и хуками. Для своего репозитория это и нужно, но `--dir` на чужой репозиторий означает
  исполнение его настроек.
- **MCP погашены** через `--strict-mcp-config` без единого `--mcp-config`, скиллы — через
  `--disable-slash-commands`, файлы сессий — через `--no-session-persistence`.
- **фан-аут запрещён**: `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=0` плюс инструмент субагента
  запрещён по имени (`--disallowed-tools Task Agent` — имя менялось между версиями, поэтому
  оба). Проверено вызовом, который прямо просили делегировать субагенту: воркер ответил
  `NO SUBAGENT`.
- **отказ на грязном дереве** — как у `agy-run`, и по той же причине: правки воркера
  откатываются только через `git checkout .`, а для этого до вызова дерево должно быть чистым.
  `--force` снимает эту проверку, проверку запрещённых каталогов — не снимает.

### Что стоит вызов (замерено 2026-09-15)

| Вызов | input | cache read | output | время |
|---|---|---|---|---|
| `--no-tools`, тривиальный промпт | 7 380 | 0 | 55 | 3 с |
| с инструментами, создать один файл | 11 497 | 24 320 | 137 | 12 с |
| с инструментами, ответить без правок | 394 | 17 408 | 917 | 17 с |
| **настоящая многофайловая задача** | **31 859** | **264 768** | **17 519** | **263 с**, 23 хода |

То есть порог вызова с инструментами — около 18 000 входных токенов на системный промпт и
определения инструментов, а создание одного файла обошлось в ~36 000. Для сравнения, у `agy` те
же операции стоят ~30 000 и ~44 000.

### Многофайловая задача: что именно мерили

Пакет на Python из девяти файлов, 210 строк: парсер, рендерер отчёта, CLI, 14 тестов. Задание —
добавить второй формат ввода (JSON Lines) с автоопределением, новую секцию в отчёт, и тесты на
то и другое. Без shell, модель по умолчанию, `--timeout-min 20`.

Результат: семь файлов изменено, один добавлен, 14 тестов стали 33, **все проходят с первого
раза** — ни одного хода на починку. Проверял прогоном тестов и запуском CLI на обоих форматах
сам; воркер, как и просили, тестов не запускал и об их прохождении не заявлял.

Итого по входу — **~296 600 токенов**, примерно в семнадцать раз больше порога вызова с
инструментами. Это и есть цифра, с которой стоит сравнивать делегирование, а не стоимость
создания одного файла.

Сопоставление с `agy`, у которого замерена задача той же формы (пять файлов, ~150 строк,
9 тестов → 19): ~116 000 input + ~575 000 cache-read + ~40 600 output за 139 с. По суммарному
входу GLM обошёлся примерно в 43% от agy при чуть большем объёме работы, но потратил вдвое
больше времени. **Задачи похожи по форме, но не идентичны** — читать как порядок величины, а не
как точное сравнение.

**`total_cost_usd` в отчёте — не счёт от Z.AI.** Claude Code считает его по своей таблице цен, в
которой GLM нет; в JSON это помечено как `"costBasis":"unknown"`. Обёртка печатает цифру, потому
что относительное сравнение вызовов по ней работает, и помечает её, потому что принимать её за
сумму к оплате нельзя. Реальный показатель — токены.

`[claude-code:unrecognized_model]` в stderr по той же причине: клиент не знает `glm-5.3[1m]`.
На результат не влияет — `modelUsage` в ответе подтверждает и модель, и `contextWindow` 1000000.

## Installed copies and junctions

Три пути вне этого репозитория — и при этом часть той же системы:

- `~/.claude/bin/glm-run.py` — установленная копия `GLM/glm-run.py`. Вызов всегда идёт в неё,
  поэтому после правки исходника здесь копию нужно переписать поверх.
- `~/.claude/skills/glm` — junction на `.claude/skills/glm/` этого репозитория, не отдельный
  файл. Именно он делает скилл `glm` видимым во всех проектах; содержимое версионируется здесь
  и правится только здесь, не через junction.
- `~/.claude/settings.json` — разрешение `Bash(python C:/Users/cupik/.claude/bin/glm-run.py:*)`,
  по которому команда проходит без вопросов. Запись сверяется с текстом команды, поэтому вызов
  пишется именно так; аргументы она не ограничивает, поэтому обёртка сама проверяет `--dir`.

## Проверка, что режим действительно сменился

В сессии Claude Code — команда `/status`: она показывает провайдера, base URL и источник
credential. Это надёжнее, чем смотреть в `settings.json`, потому что отвечает на вопрос, куда
реально уходят запросы.

## Файлы, которые создаёт скрипт

Оба появляются при первом переключении на GLM, в `~/.claude/` (вне этого репозитория):

- `zai_api_key.txt` — введённый ключ, открытым текстом;
- `settings.anthropic.backup.json` — копия `settings.json`, снятая перед первой правкой.
