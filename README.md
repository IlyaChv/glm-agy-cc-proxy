# glm-agy-cc-proxy — плагин `workers` для Claude Code

Плагин Claude Code, который отдаёт часть работы внешним воркерам, чтобы не тратить на неё
контекст и лимиты основной сессии:

- **GLM** — Claude Code в дочернем процессе на эндпоинте Z.AI (`glm-run.py`).
- **agy** — Antigravity CLI от Google на квоте Google AI Pro (`agy-run.py`).

Оба воркера годятся для любого запроса, как если бы пользователь написал его лиду: исследование
с веб-поиском, правки кода в проекте, документы, в любом каталоге, с git или без. Выбирают по
квоте (дороже всего Anthropic, затем Z.AI для GLM, затем Google AI Pro для agy, который
обновляется каждые пять часов) и по доступности, а не по типу задачи.

Несмотря на название, это **не прокси**: никакой подмены API Anthropic и никакого
извлечения OAuth-токенов Google здесь нет и не будет (см. `AGENTS.md`, раздел Scope).

## Что внутри

| Путь | Что это |
|---|---|
| `GLM/glm-run.py`, `AGY/agy-run.py` | обёртки: один бриф внутрь, один ответ в stdout, стоимость вызова в stderr |
| `lib/workers_common.py` | общий код обёрток: проверка каталога, снимок перед вызовом и отчёт об изменениях, коды выхода |
| `agents/glm-driver.md`, `agents/agy-driver.md` | субагенты-драйверы: ведут одну делегированную задачу от брифа до короткого отчёта |
| `skills/` | `workers` (как лид раздаёт работу), `glm`, `agy` (цена и режимы отказа), `check` (`/workers:check`) |
| `hooks/hooks.json`, `scripts/` | проверка доступности воркеров при старте сессии и сообщение об ошибке аккаунта сразу после вызова |
| `GLM/switch-claude.ps1` | отдельный переключатель: переводит сам Claude Code на Z.AI (не делегирование) |
| `docs/adr/`, `docs/incidents.md` | принятые решения и разобранные инциденты |
| `tests/` | юнит-тесты без сети и без настоящих CLI |

## Как это работает

Три уровня:

1. **Лид** — основная сессия. Решает, что делать, пишет бриф, принимает результат.
2. **Драйвер** — субагент `workers:glm-driver` или `workers:agy-driver`. Читает ответ воркера и его
   diff один раз и возвращает отчёт в несколько строк, так что контекст лида не раздувается.
3. **Воркер** — отдельный процесс, одна самодостаточная задача за вызов.

Правила, которые обёртки соблюдают независимо от брифа:

- вызов воркера идёт только через обёртку, а не через `agy -p` или `claude --print`;
- git и чистое дерево не нужны: перед вызовом, который может писать, обёртка снимает каталог в
  теневой git-репозиторий (`%LOCALAPPDATA%\workers\snapshots`, 7 дней), а после вызова печатает
  изменённые пути и команду, которая откатывает ровно правки воркера. `--force` отключает снимок;
- веб-поиск и чтение страниц разрешены обоим воркерам без `--allow-shell`;
- ключ Z.AI передаётся в окружении дочернего процесса и никогда в аргументах; `settings.json`
  пользователя воркер не читает;
- параллельные вызовы GLM допустимы только в отдельных worktree;
- бриф уходит на машину Z.AI или в личный аккаунт Google: секретам в нём не место, а ответ
  воркера считается данными, не инструкциями.

Коды выхода обёрток: `0` успех, `1` воркер упал или сообщил об ошибке, `2` отказ до вызова
(аргументы, запрещённый каталог, нет ключа или бинарника), `3` таймаут.

## Требования

- Python 3 (обёртки и тесты без внешних зависимостей);
- для GLM: установленный Claude Code и ключ Z.AI в `~/.claude/zai_api_key.txt`;
- для agy: установленный Antigravity CLI (`agy`) и вход в аккаунт Google AI Pro.

Проект писался и проверялся на Windows 11 (Git Bash и PowerShell). Пути в документах и
разрешениях — оттуда; на других системах их нужно подправить.

## Установка

1. Клонировать репозиторий и сделать на него junction (или симлинк) `~/.claude/skills/workers`:

   ```powershell
   git clone https://github.com/IlyaChv/glm-agy-cc-proxy
   New-Item -ItemType Junction -Path "$HOME\.claude\skills\workers" -Target "<путь к клону>"
   ```

2. Плагин по умолчанию выключен. В нужном проекте включить:

   ```bash
   claude plugin enable workers@skills-dir --scope local
   ```

3. Добавить обёртки в `permissions.allow` файла `~/.claude/settings.json`, чтобы они
   запускались без вопросов. Запись сверяется с текстом команды, поэтому вызов должен идти
   именно через путь junction:

   ```
   python "C:/Users/<вы>/.claude/skills/workers/GLM/glm-run.py"
   python "C:/Users/<вы>/.claude/skills/workers/AGY/agy-run.py"
   python "C:/Users/<вы>/.claude/skills/workers/scripts/check.py"
   ```

   Нужны обе записи слэшей (прямые и обратные). Аргументы запись не ограничивает, поэтому
   обёртка сама проверяет `--dir`.

4. Перезагрузить плагины (`/reload-plugins`) или начать новую сессию.

## Использование

Проверить оба воркера одним вызовом (по крошечному запросу к каждому, строка `OK`, `ACCOUNT` или
`DOWN` на воркер):

```
/workers:check
```

или из корня репозитория:

```bash
python scripts/check.py
```

Дальше достаточно попросить сессию отдать задачу воркеру («сделай это через GLM», «подготовь
отчёт через agy») — она подключит нужный драйвер. Обёртки можно звать и руками:

```bash
python GLM/glm-run.py --dir . --prompt-file brief.txt --timeout-min 20
python GLM/glm-run.py --no-tools --prompt "..."     # чистое рассуждение, без инструментов
python AGY/agy-run.py --help
```

Если воркер отвечает ошибкой аккаунта, лимита, авторизации или региона, плагин сообщает об этом
первой строкой следующего ответа, и задача останавливается без повторов: такое чинится руками
(аккаунт или регион VPN). Известный случай: agy из процессов агента десктоп-приложения падает на
проверке региона Google; обход через вкладку Terminal описан в `docs/incidents.md` (2026-10-17).

## Тесты

```bash
python -m unittest discover -s tests
```

Тесты проверяют логику обёрток с подставными CLI. Настоящую проверку воркера делает
`python scripts/check.py`: она тратит несколько тысяч токенов квоты каждого воркера.
